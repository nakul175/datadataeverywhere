# Agent execution instructions

1. Check → summary → next → execute or fix → check again. Read PROCESS.md; keep one authorized story active and follow steps 1–12.
2. Do not weaken criteria to obtain a pass. Never alter thresholds, workloads, lint baselines or mandatory checks to manufacture success. Criterion changes need explicit authority, a recorded rationale and new contract version.
3. Separate documentation quality, readiness, independent/human approval, merge/release and observed delivery. Offline or author-created reviewer identities cannot grant independent approval.
4. Preserve native failed/incomplete/skipped/flaky evidence and every retry. Unknown scenario IDs fail linkage; unmapped tests stay visible. Never equate assertions with accepted stories.
5. Use only authorized tools, data and environments. Do not invent owners, consent, evidence or secrets. Safely labelled assumptions cannot replace critical authority or required approvals.
6. Save evidence in a new run location, publish stable links and verify readback. After uncertain writes retrieve before retrying. New relevant inputs stale prior evidence and approval.
7. Before handoff check fresh source and external status; report exact next step and blockers. Do not revive old scheduled workflows or continue beyond authorized scope.
8. Do not load audit history by default. For integrity checks use only audit/BUNDLE-MANIFEST.json. In-bundle hashes prove byte consistency, not external trust or semantic quality.

Compose native packages through PACKAGE-CONTRACT.md and COMMAND-ROUTING.md. Do not create another root router or editable canonical ledger. Use engineering native adapters, approved task links and native QA checkers. Verify leases and trusted CI before parallel activation. All controls are conjunctive; stop only the affected transition on conflicts. Never claim live enforcement from template files.
