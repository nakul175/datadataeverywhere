# Generic product management agent bundle edition 4

This reusable bundle connects the full product hierarchy to a practical stage review and an evidence based learning loop. It has no fixed company, product, industry, platform, provider or workspace. The previous edition remains a separate historical artefact.

## Read and prepare

1. Read `documentation/Generic Product Management Operating Framework.docx` for the human guide, all stage criteria and field components.
2. Read `PRODUCT-CONTEXT.md` and complete `product-context.template.json` from actual sources. Resolve AI and personal information applicability; use `AI-ASSURANCE.md` and `ai-assurance.template.json` when relevant.
3. Read `checker/README.md` and `checker/ASSISTANT-WORKFLOW.txt`. Establish the real canonical workspace, authority and assessment scope.
4. Adopt or locate the team's canonical versioned Ready and Done checklists using `checker/team-checklists.json`. Stories and tasks reference their exact versions.
5. Review `checker/catalogue.json`, `checker/loop-quality-spec.md`, `checker/compatibility-map.json`, `QUALIFICATION.json` and `BUNDLE-MANIFEST.json` as needed.

Extract the ZIP before execution. Python 3.9 or later is sufficient for the local checker. Run checker commands from the `checker` directory. Intake templates are not automatically ingested checker documents. Map their actual sourced decisions into the supported model.

## Instruction to give the agent

Apply this framework to the product and canonical workspace I identify. Load existing records and authoritative sources before changing anything. Preserve canonical identities, source text, protected or frozen records, history and separate approval states.

Establish the actual product context, AI and personal information applicability, reviewer governance and exact assessment scope. Select the current stage: discovery, planning, ready, delivery or learning. Use the default stage profile with seven mandatory aggregate criteria per assessed item and the small visible reference sample. Use exhaustive review only for a specifically justified audit. Never count deferred, sampled out or unreviewed guidance as passed. Use summary, next and explain to inspect concise views before opening exact retained evidence.

Assess and improve the complete hierarchy: vision, strategy, roadmap, release goals, epics, stories, acceptance criteria and technical tasks. Use one canonical team Ready checklist and one Done checklist; stories and tasks link to exact versions and add only necessary item specific conditions.

At epic discovery, test the riskiest assumption with a falsifiable decision rule. Give epics and stories sourced priority rationale and a range estimate with units, basis, uncertainty and dependencies. Retain actual results and decisions rather than inventing research, effort, capacity or dates.

When AI is used, apply the seven AI evidence groups within the relevant mandatory stage gates. Establish a versioned quality controlled evaluation dataset, actual acceptance metrics and thresholds, safety and fallback tests, data rights and current applicable privacy obligations, exact model and prompt configuration, regression evidence, monitoring triggers and learning actions. Unknown required facts remain questions; examples are not universal policies.

Run automatic integrity checks and genuine semantic review for the mandatory stage criteria. Resolve any discovered material source, authority, evidence, safety or applicable obligation defect through its affected mandatory gate. Show sample findings and coverage limits honestly.

Repair supported gaps autonomously within authorised scope. Ask targeted questions only for missing facts, priorities or authority decisions, in manageable batches. Record answers and precise follow ups, apply supported revisions, invalidate only substantively affected scoped results and rerun. Continue without a fixed clarification round limit until the selected stage's mandatory criteria are satisfied; preserve an exact resumable blocker when progress requires missing information. Keep the current unanswered batch until an answer or explicit acknowledgement advances it. Acknowledgement is not an answer; acknowledged unanswered items remain pending. Reopen resolved questions automatically on actual regression. Do not weaken criteria to obtain a pass.

The reviewer registry and review witnessing process must be governed outside the authoring agent. Do not manufacture a second reviewer identity. The offline checker is advisory, even when local names and hashes match; its output cannot grant approval, readiness, launch permission or observed delivery.

After release, compare measured outcomes with declared targets and baselines. Record uncertainty, adverse effects, decisions and follow through. Feed material findings into strategy, the roadmap, future epic experiments and subsequent stories.

Save authorised improvements in the canonical workspace and read them back. Deliver the updated hierarchy, stage report, sample coverage, unresolved questions, change history, review evidence and learning actions. Keep story and task counts separate and report only evidenced completion. Coding, deployments, external messaging, new providers and services require their actual project authority.

## Edition 4 execution notes

Use scoped-v1 review and evidence bindings. A global document fingerprint is an audit identity, not a substitute for the exact target hash. Preserve unaffected current verdicts and re-review only changed dependency scopes. Keep approved, frozen and protected elements unchanged; append a separate amendment.

Synthetic fixture commands require --allow-synthetic and return synthetic_checks_satisfied; they cannot establish a real project result. The read-only summary, next and explain commands avoid loading the entire report. bind-evidence and review-hashes compute exact hashes without creating verdicts. trust-template creates an incomplete advisory intake with no verification receipt. See checker/README.md for executable examples.
